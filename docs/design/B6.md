**B6.1 CSP hardening (RENA-005), designed with B6.3.**

Files: `src/middleware.ts` (the policy block `:278-297`), new `src/app/api/csp-report/route.ts`, `next.config.js` (drop the duplicate `X-Frame-Options`, keep it in one place: the middleware).

Rig proof: Playwright test mode checkout (Elements mounts, the 3DS iframe loads), the postcode lookup, Sentry browser init, the admin coverage map, with the enforced header and a console error assertion of zero CSP violations.
Step two: a `Content-Security-Policy-Report-Only` twin: `script-src 'self' 'nonce-<n>' 'strict-dynamic' https://js.stripe.com` with `style-src 'self' 'unsafe-inline'` (307 inline style attributes stay; style nonces are not pursued), the same connect, frame, img and font sources, reporting to `/api/csp-report` (POST, 204, rate limited 60 per minute per IP via the existing `checkRateLimit`, body parsed as `application/csp-report` or `application/reports+json`, logged through `log.ts` with `documentUri` path only, `violatedDirective`, `blockedUri` host only, never query strings). The dynamic authed pages' report only twin runs the full nonce policy. A fortnight of reports, then step three (enforce) on your word, as the register holds.
Migration or config: none. Tests: middleware header assertions per route class (public static, dynamic authed, api, redirect); the report route's parsing and rate limit; Playwright checkout under the enforced step one header. Manual: one test mode payment with the enforced header (rig). Hash law: headers are not hashed; the incognito diff of all 26 routes rides the gate; expected zero markup change. Delivery WEB.
