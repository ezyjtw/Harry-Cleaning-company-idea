Parser, pure and deterministic on both platforms (no reliance on the global `URL`): `parseRenaUrl(raw, ctx)` → `{ scheme, host, path, query, hash } | null`. Grammar: absolute `^([a-z][a-z0-9+.-]*):\/\/([^/?#]*)([^?#]*)(\?[^#]*)?(#.*)?$` (case insensitive scheme and host, lowercased on output); relative `^(\/[^?#]*)(\?[^#]*)?(#.*)?$` absolutised against `ctx.origin` (`https://www.renacleaning.co.uk`); a host part containing `@`, `:` (a port) or a non host character → null; `ctx.scheme://<rest>` (`renapro` or `rena`) is rewritten to `https://<ctx.host>/<rest>` before parsing, except the legacy bare tab form `rena://mycleans` (a single segment equal to a tab key, no query or hash), which resolves to that tab with no forward. `/en` and `/en/` locale prefix stripped after parsing. Trailing slash tolerated.

`resolveLink(raw, ctx) → { kind: 'tab', tab, forward: string | null } | { kind: 'ignore', reason: 'empty' | 'unparsable' | 'foreign' | 'unowned' }`, in this order: empty → ignore; parse fails → ignore; scheme not `https` or host not exactly `ctx.host` → `foreign` (lookalikes, userinfo tricks, http); path → owning tab by the table; no owner → `unowned`; forward = the full absolute URL (`https://host/path?query#hash`) when the path is deeper than the tab root or carries a query or hash, else `null` (a bare root is a silent switch, the pre R4 grammar). `/open/pro/<rest>` (Pro) and `/open/customer/<rest>` (customer) resolve `<rest>` recursively (B8's RENA-044 web half consumes this; the other app's prefix is `unowned`).

**B5.2 One navigation classifier per shell and the statement validator (RENA-024, RENA-039, RENA-036). Overlap D, D-p.**

Files and functions: `classifyNavigation(req, state, ctx)` and `isStatementUrl(url, ctx)` in each nav.ts; `onShouldStartLoadWithRequest` (Pro `mobile/App.tsx:1535-1572`, customer `:1457-1466`) rewritten to call the classifier first and act on its verdict; `onOpenWindow` added on the pane WebView (iOS) and `setSupportMultipleWindows={false}` set (Android), both WebView props, JS only; Pro `fetchStatement` (`:1384-1398`), `onFileDownload` (`:1401-1407`) and `androidStatement` (`:1414-1429`) gated by `isStatementUrl` before `SecureStore.getItemAsync(TOKEN_KEY)` is called.

Inputs: `req = { url, isTopFrame?: boolean, navigationType?: string }`, `state = { stripeFlow: boolean }`, `ctx = { host, origin, tabRoots }`. Output verdicts: `ALLOW_IN_PANE`, `BLOCK`, `OPEN_EXTERNAL` (system browser via `Linking.openURL`, return false), `OS_HANDLE` (`Linking.openURL`, return false), `STATEMENT` (Android download path), `STRIPE_RETURN` (Pro reroute, as today), `CROSS_TAB` (the existing intercept). Rules, in this exact order:

1. `req.isTopFrame === false` → ALLOW_IN_PANE. Sub frames (Stripe Elements, 3DS challenge iframes) are never touched. Platform note: iOS supplies the flag from `mainDocumentURL`; Android hardcodes true and never fires for sub frames, so the rule is a no op there and sub frames are untouched by construction.
2. Parse with `parseRenaUrl` semantics extended to any scheme; unparsable → BLOCK.
3. Scheme `mailto`, `tel`, `sms` → OS_HANDLE.
4. Scheme `about` with path `blank` → ALLOW_IN_PANE (iOS `window.open` interim); any other non http(s) scheme (`javascript`, `data`, `intent`, `file`, `blob`) → BLOCK.
5. Scheme `http` → BLOCK, except in `__DEV__` when the host equals the dev origin's host.
6. Host equals `ctx.host` exactly (lowercase, no userinfo, no port in production): Pro and Android and `pathname === '/api/cleaner/statement'` → STATEMENT; `state.stripeFlow` and the path is not `/cleaner/onboarding-complete` or `/cleaner/stripe/connect` (with or without `/en`) → STRIPE_RETURN (today's reroute, Pro `:1548-1563`); a tab root per `tabRoots` → CROSS_TAB; otherwise ALLOW_IN_PANE.
7. Host in `STRIPE_HOSTS` = exact set {`checkout.stripe.com`, `connect.stripe.com`, `js.stripe.com`, `hooks.stripe.com`, `m.stripe.network`, `pay.stripe.com`} or suffix `.stripe.com` on a parsed host: if `state.stripeFlow` → ALLOW_IN_PANE; else → OPEN_EXTERNAL (the Express dashboard link from earnings opens in the browser, which is correct).
8. Any other https host, top frame → OPEN_EXTERNAL.

`stripeFlow` state: set true on a top frame ALLOW of a Stripe host that followed a same origin page whose path begins `/cleaner/stripe/connect` (Pro) or during a customer approve-topup or checkout (any same origin page under `/book/`, `/services/`, `/booking/` or `/pay/` immediately preceding); cleared on the next same origin top frame landing. Today's Pro logic (`:1546`) sets it on any top frame navigation; the narrowing is a deviation named below.

`onOpenWindow` (iOS): run the classifier on `nativeEvent.targetUrl` with `isTopFrame: true`; ALLOW_IN_PANE → `injectJavaScript('window.location.href = <json>; true;')` (a plain assignment, no backslashes; STRING-LAW cooked parse proof rides the gate for this one literal); otherwise the verdict's action. Android: `setSupportMultipleWindows={false}` so `window.open` loads in the same WebView and reaches the classifier. Known web callers: the Express dashboard (`cleaner/earnings/page.tsx:72`, external, correct), AddToCalendar (external), join and dispute evidence links (external).

Statement validator (036): `isStatementUrl(url)` is true iff `parseRenaUrl` succeeds, scheme `https`, host exactly `www.renacleaning.co.uk`, pathname exactly `/api/cleaner/statement` (singular, no prefix match), no userinfo. iOS `onFileDownload` and the Android intercept both call it before any SecureStore read; false → the existing "Download failed" alert and no Bearer is read or attached.

Migration or config: none. Tests (same vitest file): classifier table rows, exact: same origin page → ALLOW; same origin tab root → CROSS_TAB; lookalike host → OPEN_EXTERNAL; userinfo → BLOCK (unparsable host); http same host → BLOCK; `js.stripe.com` in flow → ALLOW; `connect.stripe.com` out of flow → OPEN_EXTERNAL; `hooks.stripe.com/3d_secure` with `isTopFrame false` → ALLOW; issuer host with `isTopFrame false` → ALLOW; `mailto:` and `tel:` and `sms:` → OS_HANDLE; `javascript:` and `intent:` and `data:` → BLOCK; `about:blank` → ALLOW; Pro Android statement exact → STATEMENT; `/api/cleaner/statements` → ALLOW_IN_PANE (not a statement); `/api/cleaner/statement?taxYear=2026` → STATEMENT; iOS statement URL on a lookalike host → validator false. Manual (DEVICE): customer test mode checkout with the 3DS test card (4000 0027 6000 3184, the inline challenge); Pro Connect round trip, incomplete and complete returns landing the dressed stripe-return room; the dispute evidence link opens the browser; a mailto from contact details; statement download on both platforms. Parked: a redirect based 3DS that leaves the top frame for an issuer host is not in use with the card Payment Element; if the test mode walk ever shows one, the rule 7 set widens on your word.

**B5.3 Session loss, native half (RENA-029). Overlap B.**

Files: Pro badges poll (`mobile/App.tsx:1009-1040`), `endWebSession` (Pro `:102-115`, customer `:99-112`), the `onNav` watcher (Pro `:1339-1343`, customer `:1317-1321`), `logout` (Pro `:451-463`, customer `:396-412`); `nextSessionLostAction` in nav.ts.

Spec: `nextSessionLostAction(prev, status, now)` is a pure reducer over `{ consecutive401: number, firstAt: number | null }`: status 200 → reset `{0, null}`; 401 → increment, `firstAt = firstAt ?? now`; 403, 5xx, 429 and network error → unchanged (never count, never reset); returns `logout: true` iff `consecutive401 >= 2` and `now − firstAt >= 5000` (two distinct ticks, not one burst) and `now − firstAt <= 180000`. The poll keeps its 60 s cadence; a 401 shortens the next tick to 15 s so the second verdict arrives within a quarter minute. On `logout: true` the existing `logout()` runs once, guarded by a `loggingOut` ref that the `onNav` watcher shares (today several panes can call logout repeatedly). `endWebSession` sends `Authorization: Bearer <token>` with the shell header so the B1a route revokes the device row and its WEB children in one transaction (D-w), then deletes the Bearer; today it sends no Bearer. The `onNav` watcher adds `isRenaOrigin(nav.url)` to the `/login(?|$)` and `/api/auth/signin` tests (a foreign `/login` never logs the user out) and accepts the `callbackUrl` form B2 emits. The customer shell has no badges poll; its native edge stays the page edge (B2's 401 door plus the watcher); no probe is added (parked below). The badges route returns 401 for a wrong role too (`src/app/api/cleaner/badges/route.ts:12-15`), which only arises for a non cleaner token, already refused at login.

Migration or config: none. Tests: the reducer table (sequence 401, 401 within 5 s → no logout; 401, 15 s, 401 → logout; 401, 200, 401 → no logout; 401, 403, 401 → logout; 401, 500, 401 → logout; 401 then 4 minutes then 401 → no logout, window reset); Playwright rig half: each L2 page with the API stubbed to 401 navigates to `/login?callbackUrl=` (B2 owns the pages; this suite references those tests). Manual (DEVICE): revoke a cleaner's device row server side (sign out everywhere from the web), the app returns to native login within two poll ticks; a 403 on the badges endpoint (stub on the rig) does not log out.
Delivery Pro OTA (watcher change in both shells). Proof RIG-AUTO plus DEVICE.
