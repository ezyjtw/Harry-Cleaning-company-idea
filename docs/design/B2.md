**Source findings that shape the design**

1. The customer shell hides inactive panes with `display: 'none'` (mobile-customer/App.tsx, TabPane). WKWebView does not fire `visibilitychange` for that, so a hidden pane gets no activation signal from the shell today. The shell only ever calls `window.__renaRefresh` from pull to refresh. This decides item 2's in-shell mechanics.
2. The shell's forward machinery already does a real page load when a tab-root URL carries a query: `tabRootKey` matches `/app/home?paid=…`, `meaningfulPayload` is true, `selectTab` forwards, the Home pane sets `overrideUri` and loads. So `?paid=<id>` works on the installed binary with no OTA.
3. `sessionStorage` is per tab and per WebView pane. A stale marker written there by the confirmation page or the My Cleans pane would never reach Home. The register's `sessionStorage rena:stale` cannot work across panes or browser tabs; item 2 proposes `localStorage` plus the `storage` event (deviation, named).
4. The services wizard already derives guest-ness from the session (`isGuest = !isAuthenticated`, services/[category]/page.tsx:361) and offers an inline sign-in link with callbackUrl. Only `book/[id]` has the fork. The server ignores `isGuest` and decides by session (api/bookings/route.ts:811). The return_url drops the minted token in account mode (StripeCheckoutForm.tsx:64 to 67). Register text confirmed exactly.
5. The login page honours a sanitised `callbackUrl`; the signup page does not (it pushes `/account` after auto sign-in). The fork's Create account path therefore needs signup to gain the same sanitiser.
6. The website dashboards already carry the R6 401 belt (`signOut({redirect:false})` then `window.location.assign('/login?callbackUrl=…')`). Home and Book's unauthorised state reuses that belt so the middleware's authenticated-redirect-away-from-/login cannot bounce it, and the customer shell's watcher regex `/\/login(\?|$)/` fires `onSessionLost`.
7. `src/components/ui/Input.tsx` already renders an error with an id, `aria-invalid` and `aria-describedby`, and has zero importers. The 054 primitive exists in spirit; the forms use raw inputs.
8. `@axe-core/playwright` is not installed. No jsdom in the test stack; the freshness module is designed dependency-injected so vitest tests it in node.
9. RENA-058 icon paths re-confirmed on disk: `public/icons/icon-192x192.png` and `public/icons/icon-72x72.png` both exist.

A document is never served from cache                |

| push, notificationclick                                                                    | handlers kept                                                                                                                 | handlers kept, icon paths unchanged and re-confirmed                                                 |

Precache at install: `/offline` plus the `/_next/static` assets its HTML references, parsed from the fetched document at install time. Today only the HTML is precached, so a person who never visited `/offline` online gets it unstyled. Activate deletes every cache whose name is not `rena-static-v6`, which purges rena-dynamic-v3, v4, v5 and rena-static-v5 from every installed client on first load after deploy.

What the offline page still works for: any same-origin document navigation when the network fails twice shows the styled offline page with Try Again. Nothing else: no API data, no other page HTML. PWA install from the manifest is unaffected. Nothing in src read cached API data or `navigator.onLine` (055 confirmed), so no feature is lost.

The Playwright isolation test above. `e2e/public-routes.spec.ts` keeps running.

**ITEM 2. Freshness and invalidation (RENA-018, RENA-025). Overlap J.**

Files and functions:

- New `src/lib/freshness.ts` (client, dependency-injected for node tests): `registerPane(name, refetch, opts)` and `markStale(panes)`.
- `src/app/[locale]/app/home/page.tsx`: the mount effect becomes `load()`; registers pane `home`; reads `?paid=<id>`.
- `src/app/[locale]/account/bookings/page.tsx` (My Cleans): the mount effect becomes `load()`; registers pane `mycleans`; the 401 belt stays.
- `src/app/[locale]/booking-confirmation/[id]/page.tsx`: Done becomes `/app/home?paid=<id>`; on SUCCEEDED writes `markStale(['home','mycleans'])`.
- Mutation sites, one line each after the server confirms: booking creation (`book/[id]` and the services wizard), cancel and reschedule accept (`booking/[id]`), recurring setup (the regular clean offer accept), top-up and finish payment. Surface names only, never ids.
- Sign-out paths clear the marker (`shell-logout`, `signOut` callers).

Contract:

- `window.__renaRefresh = refetch`, always fresh, bypasses throttling (the shell's PTR, unchanged).
- Activation signals: `visibilitychange` to visible, `pageshow` (including `persisted`), `focus`. Coalesced at 15 s per the entry (Pro Today runs 30 s under R17; one number is yours to rule, parked).
- Explicit invalidation overrides coalescing: `markStale` writes `localStorage['rena:stale'] = {panes, at}`. Every registered pane listens for the `storage` event and, if named, refetches at once and removes its name; a pane also checks the marker on mount and on every activation, so a marker written while the pane was unloaded still lands. Markers older than 60 minutes are ignored.
- `?paid=<id>` on Home: the load is already fresh (a real page load through the shell's forward); Home strips the query with `history.replaceState` so a later PTR or reload does not replay it, and clears the `home` marker.
- Stale while revalidate: existing DOM paints, data refreshes behind, skeleton only on first load.

In-shell mechanics (no OTA): Done forwards to a real `/app/home?paid=…` load (finding 2). A cancel or reschedule in another pane writes the marker; the hidden Home pane receives the `storage` event (the panes share the WebView data store) and refetches while hidden, so it is current by the time it is shown. The shell has no on-show signal (finding 1), so that is the honest mechanism until B5.
Cross-tab on the website: the `storage` event reaches every other tab of the origin; the hidden tab refetches on the event and again, coalesced, on `visibilitychange`.

Customer shell OTA-side: nothing required for item 2. For B5 (its own worded OTA): the shell could inject `window.__renaShow && window.__renaShow()` on the TabPane active flip; the web contract exposes `__renaShow` (coalesced) now so B5 needs no web change. The freeze stands; nothing shell-side ships in B2.

Migration or config: none.
Automated tests: vitest for freshness.ts in node with injected window, document and storage fakes (coalescing window, marker override inside the window, 60-minute expiry, mount-time marker, name removal). Playwright: visibility toggle asserts one refetch and a second toggle inside 15 s asserts none; writing the marker from `page.evaluate` inside the window asserts an immediate refetch; a second page writing the marker asserts the first page's refetch (cross-tab); `/app/home?paid=x` with the preview cookie asserts the query is stripped.
Manual walks: pay, Done, Home shows the clean, on the device (DEVICE).

Deviation named: localStorage, not sessionStorage (finding 3).

## Rulings and amendments (James, 2026-10-07)

B2 (two sub-batches, B2a then B2b): as designed, with the five amendments:

1. Only a definitive 401 triggers the session-loss path; 403 renders an access or account-state error and never touches the session; 429 and 5xx are retryable; network failure is offline; only a successful empty response renders empty.
2. Per-pane localStorage stale keys; explicit invalidation bypasses the 15-second coalescing (15 s for both apps); the B2a device gate proves cross-WebView storage-event propagation on iOS and Android, else `window.__renaShow?.()` moves into B2b as a worded OTA.
3. One shared callbackUrl sanitiser for login and signup, same-origin relative destinations only.
4. FieldError does not hard-code `role="alert"`; field errors use `aria-invalid` and `aria-describedby`; alert is opt-in for submit, async and form-level failures; /contact in the sweep; axe approved.
5. SW offline precache never fails install over one asset; Messages' history entry namespaces Next's state, no duplicate thread entries, tests for Back, Forward, direct entry, and Back after a role redirect.

All nine deviations approved; all three RENA-084 mechanisms build; services wizard keeps its inline sign-in; `ui/Input.tsx` deletes in B6. Ceremonial money-path drive on both roads in both modes against a pre-change control.
