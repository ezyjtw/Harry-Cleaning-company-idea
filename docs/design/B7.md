| -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |

Every row is a code object `{ class, anchorField, horizonDays, action, holds: HoldRule[] }` and every job is `runRetentionJob(matrix.<class>, { now, batch: 200 })`: select rows past the horizon and not held, apply the action in batches of 200 inside one transaction per batch, write one `DataRetentionLog` row per batch with counts only, idempotent (a re run selects nothing). Messages: the 2 year anchor is per thread (sender and receiver pair plus booking), computed as `max(createdAt)` over the thread, so a live thread is never partially redacted. Audit delete runs last and never deletes `COMPLIANCE_JOB_RUN` rows younger than 7 years.

The compliance gate fix (finding a): `processComplianceJobsDaily` claims the marker only after `runAllJobs` returns, inside the same transaction as the marker update when every job reported `success: true`; on any failure the marker is not written (retry next tick, at most once per hour via a second marker `last_compliance_attempt_at`), the summary reports `{ processed, failed: [jobName…] }`, and `releaseSchedulerLease` records a failed run when `failed.length > 0`, so `/api/health/scheduler` turns `failing` and the monitor sees it. Admin `run_all_jobs` keeps bypassing the marker (explicitly logged).

Privacy page: section 5 lines matched to the matrix; where a job cannot promise an exact moment (batching, holds) the wording becomes "up to": "Account data: retained while your account is active and for up to 6 years after closure"; "Messages: retained for up to 2 years after the last message in the conversation, then anonymised"; "Audit logs: retained for up to 7 years". The deletion page's "deleted" for messages becomes "anonymised"; the DPIA page's "Included in data export" line for messages is removed (B7.4 decides what the export holds). The UK storage sentence is corrected in B7.8. Hash law: `/privacy`, `/account-deletion` named, sanctioned, re baselined in the gate; the last updated date moves on your word.

Migration or config: none for the jobs; one nullable column `User.retentionTombstonedAt` so the 6 year tombstone is idempotent and visible. Tests: a fixture per matrix row at horizon minus one day (untouched), horizon plus one day (acted on), horizon plus one day with each hold (untouched); the compliance gate: a job that throws leaves the marker unwritten and the heartbeat `failing`, the next tick retries once per hour; message threads: a thread with one old and one new message is untouched; re run idempotence.
